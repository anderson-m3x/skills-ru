# Мастер

**Мастер** (wizard) — это bash-скрипт, который пошагово проводит человека через ручную процедуру, которую утомительно делать руками и утомительно каждый раз заново объяснять ИИ. Он открывает каждый URL, точно говорит, что нажать и скопировать, захватывает значения, пишет их куда положено (`.env`, GitHub secrets), подтверждает на каждом этапе и показывает, сколько этапов осталось. Он может настроить сторонние сервисы, провести разовую миграцию или перевести проект из одного состояния в другое.

Приятный UX уже решён в [template.sh](template.sh): прогресс по этапам, врата подтверждения, кросс-платформенное открытие URL (включая WSL), скрытый ввод секретов, идемпотентные upsert в `.env`, запись `gh secret`/`gh variable` и финальная сводка. **Ваша задача — только определить рамки процедуры и написать её этапы.** Библиотека выше маркера `STAGES` одинакова в каждом мастере; в этой одинаковости и смысл: никогда не правьте её вручную.

Мастер по умолчанию эфемерен: он делается под один запуск, сохраняется во временный путь или в `scripts/` и удаляется, когда работа сделана. Коммитьте его только тогда, когда пользователю нужен повторяемый путь настройки, который должен жить в репозитории.

## Процесс

### 1. Определите рамки процедуры

Выясните каждый ручной шаг, который должен сделать человек, и каждое значение, которое захватывается по пути. Сначала прочитайте репозиторий, не спрашивайте вслепую:

- Для настройки: `.env`, `.env.example`, `.env.*`, `README`, `docker-compose*`, конфиги фреймворка и `.github/workflows/*` (каждая ссылка на `secrets.*` / `vars.*` — это значение, которое мастер обязан произвести).
- Для миграции или перехода: текущее состояние, целевое состояние и необратимые действия между ними.

Затем покажите пользователю упорядоченный список этапов и значения, которые каждый производит, и подтвердите: он может добавить, убрать или переставить.

**Готово, когда:** каждый этап назван по порядку и про каждое захватываемое значение вы знаете (а) где человек его берёт, (б) куда оно пишется (`.env`, GitHub secret, и туда и туда, или никуда; некоторые этапы — чистые действия), и (в) секретное оно (скрытый ввод) или публичное.

### 2. Проложите путь каждого этапа

Для каждого этапа напишите точный путь, который проходит человек: какой URL открыть, что там сделать, где показывается значение, какую переменную оно заполняет: например, "Dashboard → Developers → API keys → Reveal test key → copy". Там, где вы не знаете текущий UI или точную команду, скажите об этом и спросите пользователя или сверьтесь с документацией: никогда не выдумывайте шаги, которых может не быть.

**Готово, когда:** каждый этап сведён к конкретным инструкциям, по которым мог бы пройти посторонний.

### 3. Напишите мастера

Скопируйте `template.sh` в целевой путь. Замените пример этапа вызовами `stage` — по одному на каждый шаг, в порядке зависимостей. Используйте помощники библиотеки: `stage`, `say`/`step`, `open_url`, `ask`/`ask_secret`, `write_env`, `set_secret`/`set_var`, `pause`/`confirm`. Задайте `TOTAL_STAGES` равным числу написанных этапов.

Держите планку, которую задаёт шаблон: открывайте URL до того, как спросить его значение, используйте `ask_secret` для всего секретного, `write_env` для каждого сохраняемого значения, `set_secret` только для значений, которые действительно нужны CI, и `confirm` перед любым необратимым действием. Каждый `stage` очищает экран, чтобы был виден только текущий шаг: держите этап в рамках одной сфокусированной задачи, чтобы ничего нужного человеку не уезжало вверх. Не трогайте библиотеку выше маркера.

### 4. Проверьте и передайте

- `bash -n <script>`; запустите `shellcheck`, если он доступен.
- `chmod +x <script>`.
- Не запускайте его сквозным прогоном сами: он открывает браузеры и блокируется на вводе человека. Вместо этого пройдите его статически: каждое значение из шага 1 захватывается и попадает туда, куда шаг 1 сказал, и каждое имя в `set_secret` точно совпадает со ссылкой `secrets.*` в CI.
- Скажите пользователю, как его запускать. Если это повторяемый путь настройки, закоммитьте его и сошлитесь на него из README, чтобы следующий человек запустил скрипт, а не спрашивал ИИ.
