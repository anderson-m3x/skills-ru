# Трекер задач: локальный Markdown

Задачи и спеки этого репозитория живут как markdown-файлы в `.scratch/`.

## Соглашения

- Одна фича на каталог: `.scratch/<feature-slug>/`
- Спека — это `.scratch/<feature-slug>/spec.md`
- Задачи по реализации — по одному файлу на тикет в `.scratch/<feature-slug>/issues/<NN>-<slug>.md`, нумерация с `01`, никогда не единый объединённый файл тикетов
- Состояние триажа записывается строкой `Status:` в начале файла задачи (строки ролей см. в `triage-labels.md`)
- Комментарии и история обсуждения дописываются в конец файла под заголовком `## Comments`

## Когда скилл говорит «опубликуй в трекере задач»

Создай новый файл в `.scratch/<feature-slug>/` (при необходимости создав каталог).

## Когда скилл говорит «получи соответствующий тикет»

Прочитай файл по указанному пути. Обычно пользователь передаёт путь или номер задачи напрямую.

## Операции wayfinding

Используются скиллом `wayfinder`. **Карта** — это файл, а **дочерние** файлы — тикеты.

- **Карта**: `.scratch/<effort>/map.md` (тело Notes / Decisions-so-far / Fog).
- **Дочерний тикет**: `.scratch/<effort>/issues/NN-<slug>.md`, нумерация с `01`, с вопросом в теле. Строка `Type:` записывает тип тикета (`research`/`prototype`/`grilling`/`task`); строка `Status:` записывает `claimed`/`resolved`.
- **Блокировки**: строка `Blocked by: NN, NN` в начале файла. Тикет разблокирован, когда каждый перечисленный файл имеет статус `resolved`.
- **Фронтир**: просмотри `.scratch/<effort>/issues/` в поисках файлов, которые открыты, не заблокированы и не захвачены; побеждает первый по номеру.
- **Захват**: установи `Status: claimed` и сохрани до начала любой работы.
- **Разрешение**: допиши ответ под заголовком `## Answer`, установи `Status: resolved`, затем допиши указатель на контекст (суть + ссылка) в Decisions-so-far карты в `map.md`.
