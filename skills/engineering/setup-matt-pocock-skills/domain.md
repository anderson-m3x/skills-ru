# Доменная документация

Как инженерные скиллы должны использовать доменную документацию этого репозитория при исследовании кодовой базы.

## Перед исследованием прочитай

- **`GLOSSARY.md`** в корне репозитория, или
- **`GLOSSARY-MAP.md`** в корне репозитория, если он существует: он указывает на один `GLOSSARY.md` на контекст. Читай каждый, относящийся к теме.
- **`docs/adr/`**: читай ADR, затрагивающие ту область, в которой собираешься работать. В репозиториях с несколькими контекстами также проверь `src/<context>/docs/adr/` на решения уровня контекста.

Если каких-то из этих файлов нет, **действуй молча**. Не акцентируй их отсутствие; не предлагай создавать их заранее. Скилл `domain-modeling` (запускается через скиллы `grill-with-docs` и `improve-codebase-architecture`) создаёт их лениво, когда термины или решения действительно формулируются.

## Структура файлов

Репозиторий с одним контекстом (большинство репозиториев):

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

Репозиторий с несколькими контекстами (наличие `GLOSSARY-MAP.md` в корне):

```
/
├── GLOSSARY-MAP.md
├── docs/adr/                          ← system-wide decisions
└── src/
    ├── ordering/
    │   ├── GLOSSARY.md
    │   └── docs/adr/                  ← context-specific decisions
    └── billing/
        ├── GLOSSARY.md
        └── docs/adr/
```

## Используй словарь глоссария

Когда твой вывод называет доменное понятие (в заголовке тикета, предложении по рефакторингу, гипотезе, имени теста), используй термин в том значении, в каком он определён в `GLOSSARY.md`. Не уходи в синонимы, которых глоссарий явно избегает.

Если нужного понятия в глоссарии ещё нет, это сигнал: либо ты изобретаешь язык, который проект не использует (пересмотри), либо есть настоящий пробел (отметь его для скилла `domain-modeling`).

## Отмечай конфликты с ADR

Если твой вывод противоречит существующему ADR, явно обозначь это, а не переопределяй молча:

> _Противоречит ADR-0007 (event-sourced orders), но стоит пересмотреть, потому что…_
