# Синхронизация с upstream (mattpocock/skills)

Форк не мержит upstream через `git merge`: наши файлы переведены, поэтому любой merge давал бы конфликты. Вместо этого ведётся учёт по файлам: для каждого файла скилла запоминается upstream-блоб, на котором основан наш перевод. При обновлении переводим только то, что изменилось у Мэтта.

## Состояние

`sync/state.json`:

```json
{
  "upstream": { "repo": "mattpocock/skills", "branch": "main", "commit": "<sha>", "syncedAt": "YYYY-MM-DD" },
  "files": { "skills/engineering/tdd/SKILL.md": { "upstreamBlob": "<sha>" } }
}
```

`commit` — коммит upstream, на который переведён репозиторий. `files` — карта «путь upstream → блоб, с которого сделан наш перевод». Ключи всегда в терминах upstream, даже если локально файл переименован (см. `sync/renames.json`).

## Ручной цикл

```powershell
# из каталога клона

# 1. Что изменилось у Мэтта со времени последней синхронизации
python tools\sync_plan.py --apply-copy

# 2. Разобрать sync/pending.json (правила ниже):
#    — translate: новые и изменённые файлы — перевести на русский и адаптировать под DSH;
#    — copy: уже применены флагом --apply-copy;
#    — delete: удалить локальные файлы.

# 3. Проверка
python tools\validate_skills.py
python tools\scan_untranslated.py

# 4. Зафиксировать новое состояние и обновить ссылки
python tools\sync_commit.py
python tools\install_links.py --prune

# 5. Коммит и пуш
git add -A
git commit -m "sync upstream <sha>"
git push origin main
```

`sync_plan.py` печатает человекочитаемую сводку и пишет `sync/pending.json`. `sync_commit.py` без `--to` берёт актуальный `upstream/main`, проверяет, что все пункты `pending.json` закрыты (файлы существуют/удалены, фронтматтер валиден), и только тогда перезаписывает `state.json`.

## Правила перевода и адаптации

1. **Фронтматтер.** Ключи не переименовывать. `name` — латиницей, **как в upstream**: имена скиллов не меняются, иначе перестанет работать пофайловый учёт. Переводить значения `description` и `whenToUse`. Флаги `disable-model-invocation` / `user-invocable` DSH понимает, их сохранять.
2. **Структура.** Заголовки, списки, таблицы, порядок разделов — как в оригинале. Код, команды, пути, имена файлов и API — без перевода. Комментарии в коде и человекочитаемые сообщения — переводить.
3. **Терминология.** «скилл», «субагент», «тикет», «спека», «грилл-сессия» (grilling), «глубокий модуль» (deep module), «шов» (seam), «глоссарий», ADR, tracer bullet, PR, TDD — как есть.
4. **Адаптация под DSH.**
   - `CLAUDE.md` → `AGENTS.md`; `.claude/` → `.dsh/`; Claude Code plugin/settings — вырезать или переписать как действие агента;
   - «Task tool», «subagents» → «субагент (инструмент `subagent`)»;
   - `claude --bg` → «фоновый субагент»;
   - слэш-вызовы `/name` → «скилл `name`»;
   - `agents/openai.yaml` (Codex) — удалён, упоминания вырезать;
   - если шаг требует несуществующего в DSH API — описывать намерение, а не выдуманный конфиг.
5. **Ничего не выдумывать.** Не добавлять новых разделов от себя, не менять смысл. Если фраза непереводима без потери смысла — оставить английский термин в скобках.

## Переименования

По умолчанию имён не трогаем: `sync/renames.json` пуст (`{}`), и локальные пути совпадают с upstream. Механизм оставлен на случай, когда переименование неизбежно (например, конфликт с общепринятым именем скилла в экосистеме):

```json
{ "skills/productivity/handoff": "skills/productivity/handoff-new-name" }
```

Ключ — путь upstream (папка или файл), значение — локальный путь. В этом случае после перевода `SKILL.md` нужно поправить фронтматтер: `name` → новое локальное имя. Чем меньше таких исключений, тем проще синхронизация, поэтому по умолчанию файл пустой.

## Документация (DOC/)

Полные описания скиллов лежат в `DOC/<категория>/<скилл>.md` и переводятся из `docs/<категория>/<скилл>.md` upstream. Это отдельная, менее приоритетная корзина синхронизации:

| Корзина `sync/pending.json` | Что значит | Что делать |
|---|---|---|
| `docs_new` | у Мэтта появилась страница, у нас её нет | перевести по шаблону DOC, добавить в `DOC/README.md` |
| `docs_changed` | страница у Мэтта изменилась | перевести обновление, проставить новый `@<sha>` в источнике |
| `docs_removed` | страница удалена у Мэтта | свою не удалять: в `DOC/README.md` пометить «источник удалён» |

Правила для страниц:

- шаблон: `# <скилл> — <название>` → «Что делает» → «Когда вызывать» → «Требования» → тематические разделы → «Частые вопросы» → «Признаки, что работает» → «Место в процессе» → «Пример» → «Грабли» → «См. также»;
- внизу обязательна строка `Источник: mattpocock/skills@<7 символов sha>, перевод YYYY-MM-DD`; для страниц без upstream-пары (misc, in-progress) — `Источник: своё (по SKILL.md), написано YYYY-MM-DD`;
- английские оригиналы не храним: берём `git show upstream/main:docs/...`;
- «См. также» ведёт только на существующие страницы `DOC/`;
- за один цикл синхронизации переводим не больше трёх страниц: остальные остаются в `pending.json` до следующего месяца (в отчёте — что отложено).

Проверка: `python tools\validate_docs.py` — наличие страниц, обязательные разделы, живость ссылок, совпадение `@sha` с `sync/state.json`, упоминание в оглавлении.

## Что не синхронизируется

Всё, что вне `skills/`: README, `SYNC.md`, `CHANGELOG-ru.md`, `tools/`, `sync/`, `plugins/`. Плагин `plugins/start-routes` — наша разработка, аналогов в upstream у него нет, поэтому `sync_plan.py` его не видит: сравнение идёт только по путям `skills/`. В upstream были `docs/`, `scripts/`, `.claude-plugin/`, `.github/`, changesets, `package.json` — они удалены и обратно не тянутся.

## Если upstream переименовал или удалил скилл

- переименование → поправить `sync/renames.json`, локально `git mv`;
- удаление → `sync_plan` покажет `D`, файл (или папку) удалить; если папка опустела — удалить целиком;
- переименование категории/пути → это переименование, а не удаление+создание: обновить `renames.json`, чтобы не потерять историю перевода.

## Откат

История линейная, каждая синхронизация — отдельный коммит. Откат: `git revert <commit>` или `git reset --hard <prev>` плюс восстановление `~/.dsh/skills` через `install_links.py`.
