# migrate-to-shoehorn — миграция тестов с `as` на shoehorn

## Что делает

Переводит тестовые файлы с приведений типов `as` на `@total-typescript/shoehorn`. Пакет `shoehorn` позволяет передавать частичные данные в тестах, держа TypeScript довольным, и заменяет приведения `as` типобезопасными альтернативами.

Скилл закрывает три конкретные боли `as` в тестах: приём, который приучили не использовать; необходимость вручную указывать целевой тип; double-as (`as unknown as Type`) для намеренно неверных данных.

Граница жёсткая и повторена в скилле отдельной строкой: **только тестовый код**, в продакшн-коде shoehorn не используется никогда.

## Когда вызывать

- человек упоминает shoehorn;
- нужно заменить `as` в тестах;
- нужны частичные тестовые данные — большие объекты, где важна только часть свойств.

Отдельного «когда не надо» в скилле нет; ограничение одно — прод-код мимо.

## Как работает

1. **Собирает требования** — до правок спрашивает: в каких тестовых файлах приведения `as` создают проблемы; имеет ли человек дело с большими объектами, где важна только часть свойств; нужно ли передавать намеренно неверные данные для тестирования ошибок. Ответы решают, какую из трёх функций брать.
2. **Ставит пакет** — `npm i @total-typescript/shoehorn`.
3. **Ищет кандидатов** — `grep -r " as [A-Z]" --include="*.test.ts" --include="*.spec.ts"`.
4. **Меняет `as Type` на `fromPartial()`** — для частичных данных, которые всё ещё проходят проверку типов.
5. **Меняет `as unknown as Type` на `fromAny()`** — для намеренно неверных данных; автодополнение при этом сохраняется.
6. **Добавляет импорты** из `@total-typescript/shoehorn`.
7. **Проверяет типы** — прогоняет проверку типов, чтобы убедиться, что миграция ничего не сломала.

Читает он тестовые файлы и результаты своего `grep`, а также ответы человека на шаг 1; собственных справочников рядом с `SKILL.md` нет, вся процедура в одном файле. Создаёт — правки в тестовых файлах и зависимость `@total-typescript/shoehorn` в манифесте с lock-файлом. Других артефактов не остаётся; заканчивается всё прогоном проверки типов.

### Какую функцию брать

| Функция         | Случай использования                                              |
| --------------- | ----------------------------------------------------------------- |
| `fromPartial()` | Передать частичные данные, которые всё ещё проходят проверку типов |
| `fromAny()`     | Передать намеренно неверные данные (сохраняет автодополнение)      |
| `fromExact()`   | Заставить полный объект (позже заменить на `fromPartial`)          |

## Пример

Человек: «В тестах замучили приведения — сплошные `as Request` и один `as unknown as Request`. Переведи на shoehorn».

Агент проходит шаг 1 и задаёт три вопроса: в каких файлах мешают приведения, есть ли большие объекты, где важна только часть свойств, и нужны ли намеренно неверные данные. Человек отвечает, что мешает `Request` (двадцать лишних свойств ради одного `body.id`) и что один тест специально суёт `id: 123` вместо строки. Дальше — установка и поиск:

```bash
npm i @total-typescript/shoehorn
```

```bash
grep -r " as [A-Z]" --include="*.test.ts" --include="*.spec.ts"
```

Правки в найденных тестах. Обычное приведение:

```ts
// до
getUser({ body: { id: "123" } } as Request);

// после
import { fromPartial } from "@total-typescript/shoehorn";

getUser(fromPartial({ body: { id: "123" } }));
```

Намеренно неверные данные:

```ts
// до
getUser({ body: { id: 123 } } as unknown as Request); // wrong type on purpose

// после
import { fromAny } from "@total-typescript/shoehorn";

getUser(fromAny({ body: { id: 123 } }));
```

Большой объект, от которого нужен только `body.id`, перестаёт требовать двадцать подставных свойств:

```ts
it("gets user by id", () => {
  getUser(
    fromPartial({
      body: { id: "123" },
    }),
  );
});
```

Результат: в тестовых файлах не осталось ни `as Request`, ни `as unknown as Type`; импорт `@total-typescript/shoehorn` добавлен, проверка типов прогнана и проходит. Намеренно неверный тест по-прежнему передаёт неверный тип — но уже через `fromAny()`, а не через double-as.

## Грабли

- **`grep` из скилла видит не все приведения.** Шаблон ` as [A-Z]` ловит только `as` перед заглавной буквой: `as string`, `as number`, `as any`, `as const` остаются незамеченными. Прогоняйте поиск по конкретным типам своего проекта отдельно, иначе миграция будет выглядеть законченной при живых приведениях в файле.
- **`fromAny()` глушит ошибки типов насовсем.** Он нужен только там, где неверный тип — суть теста; в остальных местах он превращает случайную опечатку в тихо проходящий тест. Каждый `fromAny()` в диффе стоит проверить отдельно, а `fromPartial()` — предпочитать по умолчанию.
- **`fromExact()` без паттерна миграции.** В таблице он есть («заставить полный объект, позже заменить на `fromPartial`»), но ни примера, ни шага замены в скилле нет. Если агент поставил `fromExact()`, это временное состояние, а не финальный код: возвращайтесь и меняйте на `fromPartial()`.
- **Соблазн утащить shoehorn в прод.** Замена механическая, и агент легко добавляет `fromPartial()` в `src/`, а не в `*.test.ts`. В DSH нет хуков Claude Code, которые запретили бы импорт вне тестов, — проверяйте дифф руками или просите отдельное ревью.
- **Окружение DSH.** Скиллы ставятся в `~/.dsh/skills`, а сама миграция идёт в вашем рабочем репозитории; команды из скилла — GNU-ориентированные, на Windows `grep -r ... --include=...` заменяется на `Select-String`. Если разносить правки по файлам между субагентами, помните про лимит: 8 активных субагентов одновременно.
