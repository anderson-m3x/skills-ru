# scaffold-exercises — скаффолдинг упражнений для курса

## Что делает

Создаёт структуру каталогов упражнений: секции внутри `exercises/`, упражнения внутри секций, подпапки вариантов (`problem/`, `solution/`, `explainer/`) и обязательные `readme.md` в каждой подпапке. Результат — дерево, которое проходит `pnpm ai-hero-cli internal lint`, после чего коммит через `git commit`.

По умолчанию скилл делает заглушки, а не содержание. Заглушка — это каталог плюс минимальный `readme.md` с заголовком и описанием; для заглушек упражнение только с readme подойдёт.

## Когда вызывать

- Нужно наскаффолдить упражнения, создать заглушки упражнений или настроить новую секцию курса.
- Есть план с секциями, упражнениями и типами вариантов, из которого нужно получить готовое дерево каталогов.
- Нужно перенумеровать или перенести существующие упражнения — в SKILL.md описан порядок через `git mv` и повторный линт.

## Как работает

1. **Разбирает план.** Извлекает имена секций, имена упражнений и типы вариантов. Это единственный вход: скилл читает план, а не придумывает структуру.
2. **Создаёт каталоги.** `mkdir -p` для каждого пути. Секции — `XX-section-name/` внутри `exercises/` (например, `01-retrieval-skill-building`), упражнения — `XX.YY-exercise-name/` внутри секции (например, `01.03-retrieval-with-bm25`). Номер секции — `XX`, номер упражнения — `XX.YY`, имена в dash-case. Подпапка варианта — хотя бы одна из `problem/` (рабочее пространство студента с TODO), `solution/` (эталонная реализация), `explainer/` (концептуальный материал без TODO). Если план не говорит иного, по умолчанию берётся `explainer/`.
3. **Создаёт заглушки `readme.md`.** По одному на каждую папку варианта, с заголовком:

   ```md
   # Exercise Title

   Description here
   ```

   `readme.md` обязателен каждой подпапке, должен быть непустым (подойдёт даже одна строка заголовка) и не содержать битых ссылок. Если в подпапке есть код, ей также нужен `main.ts` (>1 строка).
4. **Запускает линт.** `pnpm ai-hero-cli internal lint` — валидация получившегося дерева. Линтер проверяет: у каждого упражнения есть подпапки (`problem/`, `solution/`, `explainer/`); существует хотя бы одна из `problem/`, `explainer/` или `explainer.1/`; `readme.md` существует и не пуст в основной подпапке; нет файлов `.gitkeep`; нет файлов `speaker-notes.md`; нет битых ссылок в readme; нет команд `pnpm run exercise` в readme; `main.ts` обязателен для каждой подпапки, если она не состоит только из readme.
5. **Исправляет ошибки.** Повторяет до тех пор, пока линт не пройдёт.

Заканчивается всё прохождением линта и коммитом через `git commit`. Если упражнения двигались, порядок другой: `git mv` для переименования каталогов (это сохраняет историю git), обновление числового префикса для сохранения порядка, затем повторный линт.

## Пример

Человек присылает план:

```
Section 05: Memory Skill Building
- 05.01 Introduction to Memory
- 05.02 Short-term Memory (explainer + problem + solution)
- 05.03 Long-term Memory
```

Агент разбирает план, видит три упражнения и у 05.02 — три варианта, после чего выполняет:

```bash
mkdir -p exercises/05-memory-skill-building/05.01-introduction-to-memory/explainer
mkdir -p exercises/05-memory-skill-building/05.02-short-term-memory/{explainer,problem,solution}
mkdir -p exercises/05-memory-skill-building/05.03-long-term-memory/explainer
```

Затем создаёт заглушки readme — по одной строке-заголовку на файл:

```
exercises/05-memory-skill-building/05.01-introduction-to-memory/explainer/readme.md -> "# Introduction to Memory"
exercises/05-memory-skill-building/05.02-short-term-memory/explainer/readme.md -> "# Short-term Memory"
exercises/05-memory-skill-building/05.02-short-term-memory/problem/readme.md -> "# Short-term Memory"
exercises/05-memory-skill-building/05.02-short-term-memory/solution/readme.md -> "# Short-term Memory"
exercises/05-memory-skill-building/05.03-long-term-memory/explainer/readme.md -> "# Long-term Memory"
```

Дальше — `pnpm ai-hero-cli internal lint`. Если линт ругается (пустой readme, битая ссылка, забытый `main.ts`), агент правит и прогоняет его снова.

Результат: у 05.01 и 05.03 по одному варианту `explainer/` с непустым readme, у 05.02 три подпапки — `explainer/`, `problem/`, `solution/`, каждая со своим readme. Линт проходит, дерево коммитится через `git commit`.

## Грабли

- **Пустой `readme.md` или каталог без него.** Линт требует непустой readme в основной подпапке: нулевой файл не пройдёт, а заголовок — уже настоящий контент. Заодно линт ловит битые ссылки, так что ссылку на будущий файл лучше не ставить в заглушку.
- **Игнорирование плана вариантов.** По умолчанию скилл берёт `explainer/`, но если план явно перечисляет `explainer + problem + solution`, нужны все три: иначе `problem/` (рабочее пространство с TODO) и `solution/` (эталон) просто потеряются, а линт этого не заметит — у упражнения ведь есть хотя бы одна подпапка.
- **Артефакты, привычные в других репозиториях.** `.gitkeep`, `speaker-notes.md` и команды `pnpm run exercise` в readme линтер запрещает. Как только в подпапку добавляется код, ей нужен `main.ts` (>1 строка) — подпапка «только из readme» перестаёт быть таковой.
- **`mv` вместо `git mv`.** Обычный `mv` теряет историю git. После переноса или переименования нужно обновить числовой префикс, чтобы сохранить порядок, и перезапустить линт: номера `XX`/`XX.YY` должны совпадать с родительской секцией.
- **DSH-специфика.** Скиллы ставятся в `~/.dsh/skills`, хуков Claude Code здесь нет — автоматический линт «после каждой правки» не повесить, запускать руками или держать требование строкой в `AGENTS.md`. При веере задач помните про лимит субагентов 8: разбивать скаффолдинг по секциям на большее число детей не получится. И если скилл в статусе in-progress, его текст может меняться — сверяйтесь с `SKILL.md` перед прогоном.
