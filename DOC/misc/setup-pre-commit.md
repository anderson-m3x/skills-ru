# setup-pre-commit — pre-commit хуки через Husky

## Что делает

`setup-pre-commit` настраивает в текущем репозитории Husky pre-commit хук, который прогоняет проверки до создания коммита. Хук собирает три вещи в одну цепочку: **lint-staged**, запускающий Prettier на всех проиндексированных файлах, затем скрипты **typecheck** и **test**.

Файлы скилл создаёт и правит сам: `npx husky init` заводит каталог `.husky/` и добавляет в `package.json` скрипт `prepare: "husky"`, дальше появляются `.husky/pre-commit`, `.lintstagedrc` и — только если конфига Prettier ещё нет — `.prettierrc`. В devDependencies ставятся `husky`, `lint-staged` и `prettier`. Заканчивается всё коммитом, который проходит через только что поставленный хук: заодно это smoke test того, что настройка рабочая.

## Когда вызывать

Скилл вызывают, когда нужно добавить pre-commit хуки, настроить Husky или сконфигурировать lint-staged, а также когда хочется, чтобы форматирование, проверка типов и тесты гонялись на коммите. Агент подхватывает его сам, если задача сформулирована так же.

Речь про текущий репозиторий: скилл ищет lockfile и правит `package.json`, `.husky/` и конфиги прямо на месте, а не рассказывает, как настраивать хук руками.

## Как работает

1. **Определяет пакетный менеджер** по lockfile: `package-lock.json` — npm, `pnpm-lock.yaml` — pnpm, `yarn.lock` — yarn, `bun.lockb` — bun. Используется тот, что есть; если непонятно — по умолчанию npm.
2. **Ставит зависимости** как devDependencies: `husky`, `lint-staged`, `prettier`.
3. **Инициализирует Husky** командой `npx husky init`. Она создаёт каталог `.husky/` и добавляет в `package.json` скрипт `prepare: "husky"`.
4. **Создаёт `.husky/pre-commit`**. Shebang для Husky v9+ не нужен, содержимое — три строки:

   ```
   npx lint-staged
   npm run typecheck
   npm run test
   ```

   `npm` заменяется на определённый пакетный менеджер. Если в `package.json` репозитория нет скрипта `typecheck` или `test`, соответствующая строка опускается, и скилл говорит об этом пользователю.
5. **Создаёт `.lintstagedrc`**:

   ```json
   {
     "*": "prettier --ignore-unknown --write"
   }
   ```

6. **Создаёт `.prettierrc`, если конфига нет.** Только в этом случае, со значениями по умолчанию:

   ```json
   {
     "useTabs": false,
     "tabWidth": 2,
     "printWidth": 80,
     "singleQuote": false,
     "trailingComma": "es5",
     "semi": true,
     "arrowParens": "always"
   }
   ```

7. **Проверяет** чек-лист: `.husky/pre-commit` существует и исполняемый, `.lintstagedrc` существует, скрипт `prepare` в `package.json` равен `"husky"`, конфиг Prettier существует, а `npx lint-staged` запускается и работает.
8. **Коммитит**: индексирует все изменённые и созданные файлы и делает коммит с сообщением `Add pre-commit hooks (husky + lint-staged + prettier)`. Коммит проходит через новые pre-commit хуки — это и есть финальная проверка.

Порядок в хуке не случайный: сначала lint-staged (быстро, только проиндексированное), потом полные typecheck и тесты.

## Пример

Человек: «Добавь в этот репозиторий pre-commit хуки — хочу, чтобы на коммите гонялось форматирование и тесты».

В корне лежит `pnpm-lock.yaml`, а в `package.json` есть скрипты `typecheck` и `test`. Агент ставит `husky`, `lint-staged` и `prettier` в devDependencies, вызывает `npx husky init`, пишет `.husky/pre-commit` с подменой менеджера:

```
npx lint-staged
pnpm run typecheck
pnpm run test
```

Затем создаёт `.lintstagedrc`, добавляет `.prettierrc` (своего конфига Prettier в репозитории не было) и проверяет результат запуском `npx lint-staged`.

Итог: в репозитории появляются `.husky/pre-commit`, `.lintstagedrc` и `.prettierrc`, в `package.json` — `prepare: "husky"` и devDependencies, а коммит `Add pre-commit hooks (husky + lint-staged + prettier)` проходит уже через включённый хук. С этого момента любой коммит сначала форматирует проиндексированное, потом гоняет типы и тесты.

## Грабли

- **`npm` в теле хука при другом пакетном менеджере.** Строки `npm run typecheck` и `npm run test` берутся из скилла как есть; в репозитории с `pnpm-lock.yaml`, `yarn.lock` или `bun.lockb` их надо заменить на выбранный менеджер. Иначе хук будет падать на каждом коммите.
- **В `package.json` нет `typecheck` или `test`.** Хук со ссылкой на несуществующий скрипт ломает коммит. Скилл в этом случае опускает строку и сообщает пользователю — проверьте, что оставшиеся скрипты действительно есть, прежде чем коммитить.
- **Перезапись существующего конфига Prettier.** `.prettierrc` создаётся только когда конфига нет. Если записать туда дефолты поверх рабочего конфига, форматирование поедет сразу по всему репозиторию.
- **В коммит уедет лишнее.** Шаг с коммитом индексирует все изменённые и созданные файлы, а не только конфиги хуков. Посторонние правки в рабочем дереве попадут в `Add pre-commit hooks (husky + lint-staged + prettier)` — уберите их из индекса заранее.
- **Окружение DSH.** Скиллы в DSH ставятся в `~/.dsh/skills` — оттуда агент и видит `setup-pre-commit`. Хуков Claude Code (включая `/hooks` и `settings.json`) в DSH нет, но здесь это не мешает: настраиваются git-хуки Husky, а не хуки агентской среды. Отдавать такую настройку фоновым субагентам незачем, но если будете — помните про лимит в 8 активных субагентов.
